= Pi

This project provides a Command Line Interface (CLI) that automates the configuration and flashing of the following devices for immediate use:

* {orange_link}
* {raspberry_link}

This allows you to spend more time enjoying your devices rather than configuring them.

toc::[]

== Features

* Supports {orange_link} and {raspberry_link} devices.
* Uses the {xdg_link} so you can configure and manage multiple device profiles, networks, scripts, and much more.

== Requirements

* {orange_link} or {raspberry_link} hardware.
* {e2tools_link}: For flashing Orange Pi devices.
* {open_ssl_link}: For encryption.
* {curl_link}: For image downloads.

💡 Use {homebrew_link} and/or the {mac_os-config_link} project to ensure you are using the latest versions.

== Setup

To install, run:

[source,bash]
----
git clone https://github.com/bkuhlmann/pi.git
cd pi
git checkout 0.5.0
----

== Usage

To run, use:

[source,bash]
----
bin/run
----

You'll then be greeted with the following options:

----
Usage: run OPTION

Script Options:
  s:  Setup drive
  op: Create Orange profile configuration
  rp: Create Raspberry profile configuration
  rn: Create Raspberry network configuration
  c:  Create configuration
  e:  Edit configuration
  l:  List configurations
  o:  Open configurations
  d:  Delete configuration
  E:  Eject drive
  q:  Quit/Exit

Enter selection:
----

The above breaks down as follows:

* *Setup drive*: Provides a wizard that allows you to format and configure your micro SSD card for immediate use of your device. Start here, especially if you want to get up and running quickly with the default configuration.
* *Create Orange profile configuration*: Create a, per device, reusable {orange_link} {xdg_link} profile and network configuration using your default editor.
* *Create Raspberry profile configuration*: Create a, per device, reusable {raspberry_link} {xdg_link} profile using your default editor.
* *Create Raspberry network configuration*: Create a common and reusable {raspberry_link} {xdg_link} network configuration that can be shared amongst all profiles using your default editor.
* *Create configuration*: Create any {xdg_link} configuration in your default editor.
* *Edit configuration*: Edit an existing {xdg_link} configuration in your default editor.
* *List configuration*: List your entire {xdg_link} configuration via your console.
* *Open configuration*: Open and view your entire {xdg_link} configuration in your default editor.
* *Delete configuration*: Delete an existing {xdg_link} configuration.
* *Eject drive*: Eject (unmount) any micro SSD drive.
* *Quit/Exit*: Quits the CLI.

If you know which option you want to run, like setup, you can skip the interactive options shown above. Example:

[source,bash]
----
bin/run s
----

=== SSH

Once flashed and configured, you can insert your micro SSD card into your device and connect power. Then you can look for your device to show up on your local network with whatever host name you gave it.

To streamline this process further, edit your SSH configuration (i.e. `$HOME/.ssh/config`) to add your new host. Example:

----
Host demo.local
  HostName 192.168.0.123
  User demo
  IdentityFile ~/.ssh/demo
----

With SSH configured, you can SSH into your device as follows:

[source,bash]
----
ssh demo@demo.local
----

=== Scripts

After SSH'ing into your device, you'll want to run the `all` script to install all software, finish the setup, and immediately start using your device. The location differs by operating system as shown below:

{orange_link}

[source,bash]
----
cd /installers
./all
----

{raspberry_link}

[source,bash]
----
cd /boot/firmware/installers
./all
----

== Configuration

A default configuration is provided for you but you can override the defaults by setting the following environment variables (see `lib/configuration.sh` for details):

* `EDITOR`: This has no default but assumes you have this configured to run your favorite text editor. For example, if using Sublime Text, the value would be: `sublime`.
* `PI_TEMPLATES_ROOT`: Where all default templates are located for configuring your devices. _You should not need to change this_.
* `PI_TEMP_ROOT`: The temporary directory used when downloading temporary files for flashing to your devices.
* `XDG_CONFIG_ROOT`: The namespaced XDG configuration directory root. _You should not need to change this._

=== Templates

All templates can be found in the `lib/templates` directory. They are organized by device and provide the correct structure for creating profile and network configurations.

_These can't be configured, at the moment, but will be possible in the future._

=== Scripts

All scripts can be found in the `lib/scripts` directory. They are fully configurable via your XDG configuration. Here's the breakdown:

* `booters`: For automatically booting your device. Currently, only used by {orange_link} devices.
** `orange.sh`: Provides a {orange_boot_link} which, at the moment, is benign and does nothing.
* `installers`: For installing any/all software. Here's what each does:
** `system` (enabled): Ensures your system is up-to-date.
** `defaults` (enabled): Installs default programs such as DNS/Bonjour discovery, {curl_link}, and {git_link}.
** `docker` (enabled): Install rootless {docker_link} so you can then install as many containers as you wish.
** `sensors` (disabled): Installs libraries for reading temperature, CO2, humidity, and more.
** `terminus` (disabled): Installs the {terminus_link} ePaper server which can read and render the above sensor data on your ePaper devices.
** `all`: Runs all of the above in the order listed so you have only have a single script to run once logged in.
** `settings.sh` (optional): Provides common settings for the installers.
** `kit.sh` (optional): Provides common functions for the installers.

You can customize all of the above by creating an _identical_ directory and file structure within your `$XDG_CONFIG_HOME/pi` configuration. This allows you to quickly enable/disable scripts and/or add your own scripts as anything in your XDG configuration takes precedence over what is provided by this project. 🎉
